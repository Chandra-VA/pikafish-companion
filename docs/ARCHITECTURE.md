# 架构

```text
选定窗口的可见像素／框选屏幕区域／本机截图
    -> capture.py / vision.py：定位、方向、掩模模板匹配
    -> controller.py：稳定帧、轮次、同步、历史、模拟、任务取消
    -> engine.py：独立 Pikafish UCI 子进程
    -> variation.py / grading.py：真实 PV、局面分、根着法比较
    -> web_app.py：127.0.0.1 上的令牌保护 API
    -> web/：SVG 棋盘、候选、回放、走势、评分
```

- `rules.py` 校验模拟落子和王安全；不实现完整重复局面裁判规则。
- `calibrate.py` 从使用者的初始局面截图生成本机模板。
- `region_picker.py` 在独立进程显示临时桌面截图，返回物理屏幕交点；`capture.py` 校验虚拟桌面范围并仅捕捉所选棋盘及边距。
- `Launcher.cs` 为可选 Windows 启动器；根据自身路径查找环境和入口。
- `check_engine.py` 用于本机引擎与 NNUE 的独立验证。

识别使用 48×48 二值掩模、允许小范围平移和笔画偏差的匹配，并缓存去重后的模板；读取时根据邻近网格线微调交点，默认不是通用 OCR。没有可靠模板时不生成猜测棋盘。帧不稳定、识别不确定或将帅验证失败时暂停分析。

屏幕皮肤学习使用暂停时的原始区域画面和人工校正后的棋盘，将模板保存至本机 `screen-templates.npz`；原始 `templates.npz` 不被覆盖，已有皮肤样本可在两种捕捉来源间共用。区域坐标仅保留在当前运行中，来源切换与同步开关通过捕捉代次阻止旧帧覆盖新局面。

搜索使用代次标识和取消事件，过时任务不能覆盖新局面；完整的已知着法历史尽可能传入引擎。评分任务单独排队，保留每步走前的局面和 UCI 历史。

HTTP 服务只提供固定静态资源和受保护的操作入口。启动网页提供当前进程的随机令牌，本机 API 轮询更新界面。系统组件、引擎和浏览器均作为独立进程运行。
